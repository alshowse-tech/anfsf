## 🔍 简化机会分析

### 机会 1: UI/UX Harness + Evolution Harness 合并

**当前状态**:
```
UI/UX Harness:      280 行 (GenUI + 样式验证 + 个性化预算)
Evolution Harness:  350 行 (KPI 优化 + 数据飞轮 + 渐进进化)
总计：630 行
```

**简化方案**: 合并为 `ExperienceHarness`
```
ExperienceHarness:  450 行 (-29%)
- UI 合成与 KPI 优化共享数据流
- 样式验证与数据飞轮共享缓存机制
- 个性化预算与渐进进化共享配置
```

**收益**:
- 代码减少：180 行
- 文件减少：1 个
- 维护成本：-0.15 FTE

**风险**: 低 (两者功能正交，合并后职责仍清晰)

---

### 机会 2: DynamicRouter 功能内嵌

**当前状态**:
```
DynamicRouter: 180 行 (独立文件)
职责：根据项目复杂度激活 Harness
```

**简化方案**: 将路由逻辑内嵌到 `GovernanceControlPlane`
```
GovernanceControlPlane + DynamicRouter: 750 行 (原 632+180=812 行)
节省：62 行 (-8%)
```

**收益**:
- 代码减少：62 行
- 文件减少：1 个
- 调用链缩短：1 层

**风险**: 低 (路由是治理的自然延伸)

---

### 机会 3: Complexity Metrics 工具化

**当前状态**:
```
Complexity Metrics: 150 行 (独立文件)
职责：计算治理复杂度
```

**简化方案**: 转为工具函数集合
```
complexity-utils.ts: 80 行 (-47%)
- 移除类封装
- 转为纯函数导出
```

**收益**:
- 代码减少：70 行
- 复杂度降低：类 → 函数

**风险**: 无 (纯工具函数，无状态)

---

### 机会 4: OfflineOptimizer 配置简化

**当前状态**:
```
OfflineOptimizer: 300 行
配置项：5 个 (minSamples, maxSamples, calibrationInterval, confidenceThreshold, ...)
```

**简化方案**: 精简配置
```
配置项简化:
- minSamples: 10 (固定，不配置)
- maxSamples: 100 (固定，不配置)
- calibrationInterval: 24h (固定，不配置)
- confidenceThreshold: 0.8 (唯一可配置)
```

**收益**:
- 代码减少：50 行
- 配置复杂度：-80%

**风险**: 低 (默认值基于统计最佳实践)

---

### 机会 5: 测试代码复用

**当前状态**:
```
测试文件：6 个
测试代码量：600 行
重复代码：约 150 行 (25%)
```

**简化方案**: 提取测试工具
```
测试工具：test-utils.ts (50 行)
测试代码：500 行 (-17%)
```

**收益**:
- 代码减少：100 行
- 维护成本：-10%

**风险**: 无 (测试工具标准化)

## ⚠️ 风险评估与缓解

### 风险 1: Harness 合并后职责不清

**概率**: 低  
**影响**: 中  
**缓解措施**:
- 明确 ExperienceHarness 职责边界
- 编写详细 API 文档
- 代码审查时重点检查

### 风险 2: 内嵌后循环依赖

**概率**: 中  
**影响**: 高  
**缓解措施**:
- 使用依赖分析工具 (madge)
- 强制执行循环依赖检查
- CI/CD 集成依赖验证

### 风险 3: 配置简化后向后兼容

**概率**: 低  
**影响**: 中  
**缓解措施**:
- 提供配置迁移脚本
- 保留旧配置项 (标记 deprecated)
- 下个版本移除旧配置

### 风险 4: 测试覆盖率下降

**概率**: 低  
**影响**: 高  
**缓解措施**:
- 重构前后对比测试覆盖率
- CI/CD 强制 100% 覆盖率
- 人工审查测试用例
