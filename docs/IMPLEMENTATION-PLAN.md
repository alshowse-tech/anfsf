## 一、实施总览

### 1.1 从蓝图到代码的四阶段路线

```
Phase 1（6-8 周）：核心骨架平台
  → 单项目跑通阶段零到五，MVP 可用
     开发：2-3 人

Phase 2（4-6 周）：知识积累 + 测试自动化
  → 系统开始"学习"，第二个项目明显比第一个快
     开发：2-3 人

Phase 3（4-6 周）：多形态 + 外部集成
  → 多端输出、客户反馈闭环，可卖给第一个外部客户
     开发：3-4 人

Phase 4（持续）：企业级能力
  → 多租户、私有化部署、规模化
     开发：3-4 人
```

### 1.2 当前起点

- 代码量：~70,000 行 TypeScript，261 个源文件
- 测试：103 个测试文件，100% 通过率
- 流水线：17 层认知流水线串联了 L1→L4→L6→L7→L10
- 部署：Docker + Compose 全栈可运行
- 前端：React Web 可提交 PRD 并查看结果

### 1.3 实施原则

1. **每个 Phase 结束时交付可用的东西**——不做"全部做完才能用"的长分支
2. **在现有代码上演进，不重写**——重构 pipeline 编排层，保留 skills/core 模块作为能力提供方
3. **Phase 1 先跑通单项目全流程**——不追求多项目、多形态、多租户
4. **Agent 循环是地基**——基础设施调整（Agent 循环 + 检查点 + Token 预算）优先于功能开发

## 三、Phase 1 详细计划（6-8 周）

### 3.1 Phase 1 目标

> PM 提交一份 PRD → 系统分析需求（带置信度标注）→ PM 确认并锁死 → 系统生成前后端骨架（经 Agent 循环验证可运行）→ 任务拆解分发到开发 → 开发在 Gitea 上提交代码 → 系统自动标注代码来源 + 触发契约检查 → 联调通过后部署测试环境 → PM 审查测试结果 → L1 自动修复 / L2 建议修复 / L3 定位 → PM 确认发布 → 项目归档

**一个 PM + 一个前端 + 一个后端，在一个项目上跑通完整闭环。**

### 3.2 不做清单（Phase 1 明确排除）

- ✗ 多项目并行（Phase 2）
- ✗ 多形态前端输出——H5 嵌入/小程序子包（Phase 3）
- ✗ 三层知识库——只做出厂通用基线（Phase 2）
- ✗ 自动化 E2E 脚本生成（Phase 2，Phase 1 用手工测试）
- ✗ 工单系统（Phase 3，独立产品）
- ✗ 多租户（Phase 3/4）
- ✗ 私有化离线部署包（Phase 4）
- ✗ 竞品情报/行业合规自动获取（Phase 3）
- ✗ 经验自动模式提取（Phase 2）
- ✗ 组织级项目健康度看板（Phase 4）

| 维度 | 描述 |

**T-002：Agent 循环层实现**

| 维度 | 描述 |
|------|------|
| 目标 | 实现"生成→验证→修复"轻量 Agent 循环，用于骨架生成和代码修复 |

| 验收标准 | 输入需求规格 → 生成骨架代码 → 自动编译验证 → 有错误自动修复（最多 3 轮）→ 输出验证过的代码；3 轮后仍有错误的场景正确上报 |

**T-003：检查点与恢复机制**

| 维度 | 描述 |

| 验收标准 | 阶段一完成后检查点写入；模拟崩溃后重启，从检查点恢复；重复执行同一阶段不产生副作用 |

**T-004：Token 预算与成本追踪**

| 维度 | 描述 |

## 七、团队配置

### 7.1 当前实际：1 人团队

ANFSF 项目团队目前只有 PM 1 人，该角色同时承担前端和后端开发工作。

这对 Phase 1 实施的影响：
- 不需要多用户权限的前端界面（单人使用，先用 API + 简化界面）
- 不需要任务分发功能（所有任务由同一人完成）
- 前端界面优先做 PM 确认页和测试审查页，开发工作台可以简化
- Phase 1 周期从 6-8 周延长至 10-14 周（1 人承担全部工作）

### 7.2 Phase 1 优先级调整（1 人模式）

```
依旧必须做的（核心价值）：
  ├── Pipeline 状态机 + Agent 循环 + 检查点（地基组）
  ├── 阶段一完整实现（PRD 预检 → 置信度标注 → PM 确认 → 骨架生成）
  ├── Gitea webhook + 代码标注
  └── 提交即触发验证 + 故障报告

可以简化的（1 人不需要）：
  ├── 多角色权限管理 → 先硬编码单用户，Phase 3 再加
  ├── 任务分发界面 → 先直接看 TASK.md 文件
  ├── 开发个人工作台 → 先不做前端，用 Gitea + TASK.md 替代
  └── 组织级项目健康度看板 → Phase 4

可以延后的：
  ├── L1/L2/L3 分级修复的完整前端 → 先做 CLI 版本
  └── PM 测试审查界面 → 简化为命令行输出 + 文件报告
```
